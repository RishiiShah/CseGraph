# ATSE-1000: Agent Token Surface Economy (user-facing)

ATSE-1000 governs prose that a user or coding agent reads: CLI summaries,
Markdown output, warnings, continuation reasons, graph/path summaries, and
minimal-tool summaries.

## Rules

1. Use telegraphic prose. Drop articles, filler, and unnecessary copulas:
   `The target symbol does not fit the current budget.` becomes
   `target symbol does not fit current budget.`
2. Never alter code, code spans, paths, symbols, node IDs, URLs, quoted
   strings, or JSON keys. These are transmitted byte-for-byte.
3. Emit one fact per line. Do not repeat the same explanation in a heading,
   body, and continuation reason.
4. Keep human-readable prose within 1000 tokens per response. Code slices and
   structured payloads continue to use the request's `token_budget`.
5. Prefer a concrete action over an apology or a description of the action.

## Implementation

`csegraph._core.text.compression.terse_prose` is the canonical ATSE-1000
compressor. It is applied to CLI prose, context warnings/continuations, graph
summaries, and minimal-tool summaries. Path summaries are already terse and
are preserved verbatim because they contain bare symbol names.

The 1000-token limit is an authoring target. The compressor removes filler;
it does not truncate text or enforce that limit. Request token budgets are
enforced separately for context payloads.
